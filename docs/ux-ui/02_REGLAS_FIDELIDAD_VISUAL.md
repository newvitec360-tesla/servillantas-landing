# Reglas de fidelidad visual UX/UI

## 1. Referencias obligatorias

El equipo debe revisar antes de diseñar o programar:

- `prototypes/reference/Login.html`
- `prototypes/reference/demo_mockup_servillantas_el_puente_pro.html`
- `public/assets/brand/logo-servillantas-el-puente.jpg`

## 2. Lenguaje visual aprobado

La línea visual base usa:

- rojo Servillantas como acento principal;
- fondos blancos y grises suaves;
- laterales oscuros en administración;
- tarjetas con bordes redondeados;
- sombras suaves;
- KPIs visibles;
- estados por color;
- tablas limpias y respiradas;
- foco en lectura rápida.

## 3. Desktop

La versión escritorio debe mantener:

- sidebar lateral oscuro;
- logo visible en la parte superior del sidebar;
- topbar con buscador global;
- cards amplias;
- tablas con filtros;
- KPIs superiores;
- acciones a la derecha de cada módulo;
- colores sobrios, sin saturar.

## 4. Mobile

La versión móvil NO es una reducción del escritorio. Debe ser una experiencia propia:

- navegación inferior fija;
- pantallas de una columna;
- cards táctiles grandes;
- buscador dominante;
- acciones rápidas;
- contenido priorizado;
- menos tablas y más listas;
- foco en gestores y portal deudor.

## 5. Estados visuales

| Estado | Color | Uso |
|---|---|---|
| Verde | Pagado / recuperado / positivo | pagos aprobados, recuperación |
| Amarillo | Preventivo / seguimiento | promesas, validaciones pendientes |
| Naranja | Riesgo medio | cartera S2, mora moderada |
| Rojo | Crítico / S3 / jurídico | deuda crítica, alertas |
| Gris | Inactivo / no disponible | sin contacto, sin dato |

## 6. Prohibiciones

- No usar bootstrap genérico sin adaptar identidad.
- No mezclar clases desktop en mobile.
- No convertir tablas desktop en tablas horizontales infinitas para mobile cuando se puede usar lista/card.
- No cambiar logo, proporción o colores sin aprobación.
- No borrar los prototipos de referencia.
